# Plugin: Clipboard manager

Track clipboard history and allow pasting previous entries from the
launcher.

## Scope

- Monitor clipboard changes in the background
- Store history (text, images, rich text) with timestamps
- Search/filter clipboard history by content
- Select an entry to paste it (copy to clipboard + optional
  simulated Cmd+V)
- Configurable history size limit
- Option to pin frequently used entries

## Custom UI layout

Horizontal split-pane layout:

- **Left panel:** Scrollable vertical list of clipboard entries, most
  recent first. Each entry is a single normal-height row showing:
  - Content type heroicon (text, image, file, link, etc.) — source
    app icon deferred to separate todo
  - One line of truncated content (text preview, filename, URL, or
    content type label for images)
- **Right panel:** Preview of the currently selected entry. Adapts to
  content type:
  - Text: rendered text block, not selectable (action is always
    Enter to paste the whole entry)
  - Image: displayed at a reasonable size within the available area
  - Files: file metadata / path
  - Content truncated to fit the available area

### Interaction

- Arrow keys navigate the left panel list
- Enter pastes the selected entry (writes to clipboard + dismisses)
- Search input filters history by content (fuzzy match on text,
  filename match on files)
- Delete key removes an entry from history
- Secondary action (tab / action palette) to pin an entry

### Pinned entries

Pinned entries persist at the top of the list regardless of age.
Visually separated from the chronological entries below.

## Platform abstraction

Uses the same pattern as `AppDiscovery` / `SettingsDiscovery`:

```
platform/
  clipboard.rs                   # ClipboardPlatform trait
  macos/
    clipboard.rs                 # MacosClipboardPlatform
  fallback/
    clipboard.rs                 # FallbackClipboardPlatform (no-op)
```

`PlatformClipboard` type alias in `platform/mod.rs` via `cfg`, passed
to the plugin at construction time.

### ClipboardPlatform trait

```rust
use clipboard_rs::ClipboardContext;

pub trait ClipboardPlatform: Send + Sync {
    fn is_sensitive(&self, clipboard: &ClipboardContext) -> bool;
    fn is_self_written(&self, clipboard: &ClipboardContext) -> bool;
    fn mark_self_written(&self, clipboard: &ClipboardContext) -> Result<()>;
}
```

All clipboard monitoring and content read/write goes through
`clipboard-rs` directly (cross-platform). The trait only handles
platform-specific concerns:

- **`is_sensitive`**: Checks `available_formats()` for concealed /
  transient / auto-generated markers. macOS impl checks for
  `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`,
  `org.nspasteboard.AutoGeneratedType`, legacy markers, `dyn.*` prefix.
  Other platforms fill in their conventions when implemented.
- **`is_self_written`**: Checks for our self-write marker in the
  formats to avoid recording our own pastes from history.
- **`mark_self_written`**: Sets the self-write marker (e.g.,
  `set_buffer("org.torchsnap.fromTorchsnap", ...)`) when pasting from
  history.

### What stays cross-platform (clipboard-rs)

- Clipboard monitoring (`ClipboardWatcherContext`, `ClipboardHandler`)
- Content reading (`get_text`, `get_image`, `get_files`, etc.)
- Content writing (`set_text`, `set_buffer`, etc.)
- Format inspection (`available_formats`, `has`, `get_buffer`)
- 500ms polling interval (hardcoded in clipboard-rs)
- Shutdown via `WatcherShutdown`

## Storage

### Retention

30-day retention policy. Entries older than 30 days are deleted on
a cleanup pass. Configurable later (see clipboard-plugin-settings
todo).

### Schema (SqlStorage)

```sql
CREATE TABLE clipboard_entries (
    id          TEXT PRIMARY KEY,    -- ULID
    captured_at TEXT NOT NULL        -- ISO 8601 timestamp
);

CREATE INDEX idx_entries_captured_at ON clipboard_entries(captured_at);

CREATE TABLE clipboard_content (
    entry_id    TEXT NOT NULL REFERENCES clipboard_entries(id),
    format      TEXT NOT NULL,       -- "text", "html", "rtf", "image", "files"
    content     TEXT,                -- text-based content, NULL for binary
    file_key    TEXT,                -- FileStorage key, NULL for text
    PRIMARY KEY (entry_id, format),
    CHECK (
        (content IS NOT NULL AND file_key IS NULL) OR
        (content IS NULL AND file_key IS NOT NULL)
    )
);

-- FTS5 full-text search index on text content
CREATE VIRTUAL TABLE clipboard_fts USING fts5(
    content,
    content=clipboard_content,
    content_rowid=rowid
);

-- Keep FTS index in sync via triggers
CREATE TRIGGER clipboard_fts_insert AFTER INSERT ON clipboard_content
WHEN NEW.content IS NOT NULL BEGIN
    INSERT INTO clipboard_fts(rowid, content) VALUES (NEW.rowid, NEW.content);
END;

CREATE TRIGGER clipboard_fts_delete AFTER DELETE ON clipboard_content
WHEN OLD.content IS NOT NULL BEGIN
    INSERT INTO clipboard_fts(clipboard_fts, rowid, content)
        VALUES ('delete', OLD.rowid, OLD.content);
END;
```

Text formats (`text`, `html`, `rtf`) populate `content`. Binary
formats (`image`) populate `file_key` pointing to
`FileStorage("content")`. All available representations are stored
so restoring an entry writes back the full original format set via
`clipboard-rs`'s `set(Vec<ClipboardContent>)`.

### Querying

Full-text search via FTS5 virtual table (persisted, not in-memory).
No in-memory cache — queries hit SQLite directly. FTS5 provides
tokenized search, prefix matching, and ranking out of the box.

Search query: `SELECT ... FROM clipboard_content JOIN clipboard_fts
ON clipboard_content.rowid = clipboard_fts.rowid WHERE clipboard_fts
MATCH ?` with the user's search terms.

For the list display (no search active), a simple
`ORDER BY captured_at DESC LIMIT N` on `clipboard_entries` joined
with the text content for the preview line.

## Privacy

- Sensitive content filtered via `ClipboardPlatform::is_sensitive()`
  (see platform abstraction above)
- Auto-expire entries after 30 days (configurable later)
- Clear history command

## Research: macOS clipboard monitoring (2026-03-26)

### Tauri ecosystem options

#### Official: `tauri-plugin-clipboard-manager` (already in use)

The official Tauri plugin (`tauri-plugin-clipboard-manager` v2.3.2) is
**already integrated** in the project — used by the emoji plugin for
write operations. However, it only supports **basic read/write** (`readText`,
`writeText`, `readImage`, `writeImage`). **No monitoring, no change events,
no watch API.** Not sufficient for a clipboard history manager.

Currently only `clipboard-manager:allow-write-text` capability is granted.

#### Community: `tauri-plugin-clipboard` (CrossCopy) — recommended

**Crate:** `tauri-plugin-clipboard` on crates.io
**GitHub:** https://github.com/CrossCopy/tauri-plugin-clipboard

Purpose-built for clipboard history in Tauri v2. Uses `clipboard-rs`
internally.

**Architecture:** A background Rust thread runs `clipboard-rs`'s
`ClipboardWatcherContext`, detects changes, and emits a lightweight
"update" Tauri event (without transmitting content). The frontend then
calls back to read the actual content.

**Supported content types:** plain text, HTML, RTF, images (base64 PNG),
files (file URIs).

**Events emitted:**

| Event | When |
|---|---|
| `plugin:clipboard://clipboard-monitor/update` | Any clipboard change |
| `plugin:clipboard://text-changed` | Text content changed |
| `plugin:clipboard://image-changed` | Image content changed |
| `plugin:clipboard://html-changed` | HTML content changed |
| `plugin:clipboard://rtf-changed` | RTF content changed |
| `plugin:clipboard://files-changed` | File list changed |
| `plugin:clipboard://clipboard-monitor/status` | Monitor started/stopped |

**Rust side:**
```rust
pub fn start_monitor<R: Runtime>(&self, app_handle: AppHandle<R>) -> Result<(), String> {
    let _ = app_handle.emit("plugin:clipboard://clipboard-monitor/status", true);
    let monitor = ClipboardMonitor::new(app_handle.clone());
    let mut watcher = ClipboardWatcherContext::new().unwrap();
    watcher.add_handler(monitor);
    // spawns a thread calling watcher.start_watch() (blocking)
}
```

**TypeScript side:**
```typescript
import { onTextUpdate, startListening, stopListening } from "tauri-plugin-clipboard-api";

const unlistenText = await onTextUpdate((newText) => {
  console.log("New clipboard text:", newText);
});
const unlistenMonitor = await startListening();

// Later:
await unlistenMonitor();
unlistenText();
```

**Consideration:** This is a separate crate from the official
`tauri-plugin-clipboard-manager` already in the project. Both could
coexist, but it may be cleaner to migrate away from the official plugin
or wrap both behind our own abstraction. Worth evaluating whether
CrossCopy's plugin also covers the write operations we use in the emoji
plugin, to avoid having two clipboard plugins.

### Underlying Rust crates

#### `clipboard-rs` — best option for monitoring

**Crate:** https://crates.io/crates/clipboard-rs
**GitHub:** https://github.com/ChurchTao/clipboard-rs

Used internally by `tauri-plugin-clipboard`. Provides full monitoring
via `ClipboardWatcher` trait + `ClipboardWatcherContext`.

On macOS: polls `NSPasteboard.changeCount` every **500ms** using
`recv_timeout` on an `mpsc` channel (for graceful shutdown).

```rust
use clipboard_rs::{
    Clipboard, ClipboardContext, ClipboardHandler,
    ClipboardWatcher, ClipboardWatcherContext,
};

struct MyHandler { ctx: ClipboardContext }

impl ClipboardHandler for MyHandler {
    fn on_clipboard_change(&mut self) {
        if let Ok(text) = self.ctx.get_text() {
            println!("New text: {}", text);
        }
    }
}

fn main() {
    let handler = MyHandler { ctx: ClipboardContext::new().unwrap() };
    let mut watcher = ClipboardWatcherContext::new().unwrap();
    let shutdown = watcher.add_handler(handler).get_shutdown_channel();
    std::thread::spawn(move || watcher.start_watch());
    // shutdown.stop() from any thread
}
```

**Content reading API:**
```rust
let ctx = ClipboardContext::new().unwrap();
ctx.get_text()       // plain text
ctx.get_rich_text()  // RTF
ctx.get_html()       // HTML
ctx.get_image()      // RustImageData
ctx.get_files()      // Vec<PathBuf>
```

#### Other crates (not recommended)

- **`clipboard-master`**: Older, simpler. Has monitoring but lacks rich
  content-type read API. `clipboard-rs` is strictly better.
- **`arboard`** (1Password): Read/write only, no monitoring.
- **`copypasta`**: Read/write only, no monitoring.

### macOS `NSPasteboard.changeCount` — how it works

`NSPasteboard.changeCount` is a monotonically increasing integer
maintained by the system pasteboard server (`pasteboardd`). It
increments on every write to the general pasteboard by any app.

**Key properties:**
- Reading `changeCount` is extremely cheap — no pasteboard data is
  copied, just a syscall to `pasteboardd`.
- The counter can skip values if multiple writes happen between polls.
  You detect "at least one change," not a count of changes.
- No native notification/KVO/delegate exists on macOS (unlike iOS's
  `UIPasteboard.changedNotification`). **Polling is the only option.**

### Polling interval

| App/Library | Interval |
|---|---|
| `clipboard-rs` | 500ms |
| Maccy | ~0.5–1.0s (configurable) |
| Clipy | ~0.5s |
| Flycut | ~0.5s |
| Alfred | ~0.5s |

**500ms is the ecosystem standard.** Do not go below 250ms — no real
benefit, wastes CPU.

### No notification-based alternative exists

Every major macOS clipboard manager (Maccy, Clipy, Flycut, Alfred) uses
polling. There are no private APIs that third-party apps can reliably
use for clipboard change notifications.

### Gotchas

1. **Rapid copies are merged.** If a user copies twice faster than the
   poll interval, only the last content is seen. Accepted by all
   clipboard managers.

2. **Self-write re-entry.** When our manager pastes a history item back
   to the clipboard, `changeCount` increments, causing a false detection.
   **Solution:** Write a custom pasteboard type as a marker (e.g.,
   `org.torchsnap.clipboard-self-write`) and skip entries containing it.
   Maccy uses `org.maccy.fromMaccy` for this.

3. **Dynamic UTIs (`dyn.*`).** Legacy apps produce auto-generated UTI
   types with `dyn.` prefix. These are opaque compatibility bridges and
   should be filtered out entirely.

4. **Microsoft Office noise.** Types like `com.microsoft.ole.source` are
   metadata only — filter them.

5. **`org.nspasteboard.source`** contains the bundle ID of the
   originating app. Useful for display attribution.

### Pasteboard types to handle

#### Standard content types

| UTI | Content |
|---|---|
| `public.utf8-plain-text` | Plain text |
| `public.rtf` | Rich Text Format |
| `com.apple.flat-rtfd` | RTF with attachments |
| `public.html` | HTML |
| `public.png` | PNG image |
| `public.tiff` | TIFF image |
| `com.adobe.pdf` | PDF |
| `public.file-url` | File URL |
| `public.url` | Generic URL |

#### Privacy/sensitivity markers (MUST check before recording)

| Type | Meaning | Action |
|---|---|---|
| `org.nspasteboard.TransientType` | Ephemeral, not intentionally copied | **Skip entirely** |
| `org.nspasteboard.ConcealedType` | Sensitive (passwords, tokens) | **Skip entirely** |
| `org.nspasteboard.AutoGeneratedType` | App-generated, not user action | **Skip history** |

#### Legacy sensitivity markers (backward compat)

| Type | Application |
|---|---|
| `de.petermaurer.TransientPasteboardType` | TextExpander, Butler |
| `com.typeit4me.clipping` | TypeIt4Me |
| `Pasteboard generator type` | Typinator |
| `com.agilebits.onepassword` | 1Password (legacy) |

**Detection in Rust:**
```rust
let types = pasteboard.types(); // Vec<String>
let dominated_sensitive_types = [
    "org.nspasteboard.ConcealedType",
    "org.nspasteboard.TransientType",
    "org.nspasteboard.AutoGeneratedType",
    "de.petermaurer.TransientPasteboardType",
    "com.typeit4me.clipping",
    "Pasteboard generator type",
    "com.agilebits.onepassword",
];
let dominated_prefix = ["dyn."];

if types.iter().any(|t| dominated_sensitive_types.contains(&t.as_str()))
    || types.iter().any(|t| dominated_prefix.iter().any(|p| t.starts_with(p)))
{
    return; // skip this clipboard change
}
```

### 1Password browser extension caveat

1Password's native macOS app sets `org.nspasteboard.ConcealedType`, but
**browser extension copies go through the web clipboard API and bypass
NSPasteboard conventions entirely.** This is a known limitation across
the ecosystem — no clipboard manager can reliably detect these.

### Recommended approach for implementation

1. **Use `tauri-plugin-clipboard` (CrossCopy)** as the Tauri integration.
   It provides the monitoring thread, the JS/Rust event bridge, and
   content reading out of the box. Alternatively, use `clipboard-rs`
   directly if tighter control over the monitoring loop is needed
   (e.g., to inspect raw pasteboard types for privacy filtering before
   the content is even read).

2. **The underlying engine is `clipboard-rs`** either way, polling
   `NSPasteboard.changeCount` every 500ms.

3. **Filter on every change event:** check for concealed/transient types,
   `dyn.*` prefixes, self-write markers, and Office noise before
   recording history.

4. **Store history** with: content (text/image/files), content type,
   source app bundle ID (from `org.nspasteboard.source`), timestamp.

5. **Self-write marker:** When pasting from history, set a custom
   pasteboard type (e.g., `org.torchsnap.fromTorchsnap`) alongside the
   content. On next poll, if this type is present, skip recording.

### Decisions

- **DECIDED:** Use `clipboard-rs` directly — gives full control over
  the monitoring loop and privacy filtering at the pasteboard-type
  level before content is ever read into memory. CrossCopy plugin
  rejected as unnecessary abstraction.
- **DECIDED:** SqlStorage + FileStorage for persistence (ADR 0018/0019).
  One SQLite DB per plugin, binary blobs on disk.
- **DECIDED:** 30-day retention by age, not by entry count.
- **DECIDED:** Store all content representations, restore full format
  set when pasting from history.
- **DECIDED:** Platform abstraction via `ClipboardPlatform` trait for
  privacy filtering and self-write detection.
- **DECIDED:** Content-type heroicons instead of source app icons for
  initial implementation (source app deferred).
